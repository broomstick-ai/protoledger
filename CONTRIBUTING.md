# Contributing to protoledger

The most valuable contributions are **fixtures** (real native threads from a
harness version we have not seen) and **adapter fixes** that lower a loss
score. Both are measured by the conformance suite, so a PR shows its own value.

## Running the suite

```sh
cargo test                                   # everything
FIXTURE=codex cargo test --test fixtures     # one format
FIXTURE=codex/legacy-tool-calls cargo test --test fixtures
UPDATE_REPORTS=1 cargo test --test fixtures  # rewrite tests/reports/ after an improvement
```

`tests/reports/` is a ratchet. A loss score may go down in a PR, never up.

## Adding a fixture

```
fixtures/<format>/<case>/
  native/        the harness's own files, laid out exactly as the harness stores them
  SOURCE.md      where it came from (required, see below)
  expect.json    optional: known exceptions
```

- `native/` holds one file (a single-file format) or a tree (Claude Code's
  `<session>.jsonl` plus `<session>/subagents/…`, opencode 1.x's
  `storage/…`). The suite passes the single file, or the directory, to the
  importer.
- **`SOURCE.md` is required.** It says where the data came from (a URL and
  commit, or "generated by running <harness> <version> on <date>", or
  "synthetic, written from <source file> at <commit>"), its license, and what
  was sanitised. Never commit a transcript you do not have the right to
  publish, or one that holds secrets, personal paths or private prose.
  Generated fixtures should use neutral prompts in a throwaway directory, with
  the home directory rewritten to `/home/user`.
- `expect.json` keys: `self_exact` (false only with a `self_reason`), and
  `skip_cross` (`{"<format>": "<reason>"}`).
- Name cases for what they exercise: `tool-calls`, `subagent`,
  `compaction`, `large-tool-output`, `v1-json-storage`, `mixed-versions`.

## Writing or changing an adapter

An adapter is `src/formats/<format>.rs` (or a directory module). It implements
`formats::Format`. The rules, which the suite enforces:

1. **Self trip is exact.** `export(import(F))` reproduces F byte for byte.
   Keep each native record in `native.record` on the first event made from
   it, and have the exporter emit it unchanged when every part of it is
   present. `native.record` holds the record's exact bytes (SPEC §4), so it
   comes back as written; protoledger builds `serde_json` without
   `preserve_order` and `arbitrary_precision`, so never rebuild a record from
   its parsed `Value` and expect the same text (keys sort, numbers re-spell).
   Use `native.raw` only when the format's own serialiser does not
   round-trip through JSON (SPEC §4, §7.1).
2. **Ids are deterministic.** Event ids come from native ids (`<id>`,
   `<id>#<n>` for part *n*, `@<byte offset>` when the source has none).
   Native ids minted on export come from `util::uuid_for(event_id)` or
   `util::short_id`.
3. **Everything neutral that the format can express is filled in.** The
   neutral `kind` and `body` are what other harnesses get. Map as much as the
   format carries (SPEC §3). Anything left over stays only in `native`, with
   kind `native` if nothing neutral applies.
4. **Export renders foreign events.** A ledger imported from another format
   has no native records for you. Render it from the neutral fields, and name
   every loss with a stable `Losses` code (`reasoning-sealed-dropped`,
   `media-dropped`, `subagent-inlined`, …).
5. **Carry.** When `ExportOptions::carry` is set and the format tolerates an
   extra field on a record, attach the events that record represents with
   `carry::attach`. On import with `restore_carried`, `carry::take` them back.
   If the format cannot carry, say so in its doc.
6. **Agents are files.** A harness-native subagent becomes its own ledger with
   `agent.parent = {agent, event, relation: subagent}`. An agent started by an
   orchestrator outside the harness is a root with a `spawned-by` link; never
   render a link as a native subagent.
7. **Version callouts.** When the native shape changed between producer
   versions, add a `Variant` per shape, detect it, and document the switch in
   `docs/formats/<format>.md`. Extract the producer version wherever the
   format records it, and do not assume one version per file.
8. **Document it.** `docs/formats/<format>.md`: variants and versions, where
   the harness stores its data, the record → kind mapping, every loss code, how
   carry works, and what is unverified.
