# protoledger

**One ledger for coding-agent threads, convertible to and from every harness.**

Claude Code, Codex, opencode and a dozen other agent harnesses each store a
conversation in their own shape. protoledger is a single, harness-neutral,
append-only record of a thread, plus importers and exporters that move a thread
between those shapes with as little loss as each harness allows:

```sh
protoledger convert claude-code codex ~/.claude/projects/-home-me-app/<session>.jsonl -o out/
protoledger import auto ./rollout-2026-10-16T10-00-00-<id>.jsonl -o ledger/
protoledger export opencode ledger/ -o out/       # an `opencode session import`-able file
protoledger roundtrip claude-code <session>.jsonl --via codex   # what would a trip lose?
```

No daemon, no service: a CLI and a Rust crate.

## Why another format

Plenty of tools *read* agent transcripts (for viewing, analytics, training
data). Very few write a thread back so a harness can **resume** it, and none
keep enough to bring the thread home again unchanged. protoledger is built for
the round trip:

- **One file per agent.** A thread is `<agent>.jsonl`; its subagents are their
  own files that point at their parent. Deleting a thread is deleting a file.
- **Append-only.** Events never change once written.
- **Neutral and native.** Every event has a neutral `kind`/`body` that any
  exporter can render, and keeps the harness's original record, so exporting
  back to the same harness is byte-exact.
- **Carry.** When a harness tolerates an extra field, the exporter stows the
  protoledger events there, so Claude Code → Codex → Claude Code comes back
  exact even though Codex could not express everything.
- **Losses are named and measured.** Every importer and exporter reports what it
  could not represent, and the test suite measures every trip.

verified against the real harness.

## How well does it convert?

[`tests/reports/MATRIX.md`](tests/reports/MATRIX.md) is regenerated by the test
suite. For every fixture it shows whether X → protoledger → X is byte-exact, and
the **neutral loss score** of X → protoledger → Y → protoledger without carry:
the number of facts that did not survive Y. With carry, every trip through
Claude Code, Codex and opencode comes back exact.

## Fixtures

`fixtures/<format>/<case>/` holds real threads in each harness's own layout,
each with a `SOURCE.md` naming its origin, license and sanitisation. Some were
generated by running the harness itself; some come from permissively licensed
projects (letta-ai/trajectory, Harbor, agentsview, transession, sessionport and
others, credited in each `SOURCE.md`); a few are synthetic, written from the
harness's own schema code and labelled as such.

**New harness version? Send a fixture.** See [CONTRIBUTING.md](CONTRIBUTING.md).

## Library

```rust
use protoledger::formats::{self, ImportOptions, ExportOptions};

let codex = formats::by_name("codex").unwrap();
let claude = formats::by_name("claude-code").unwrap();
let imported = claude.import(path, &ImportOptions::standard())?;
let exported = codex.export(&imported.set, &ExportOptions::standard())?;
for loss in &exported.losses.0 {
    eprintln!("{} ×{}", loss.code, loss.count);
}
exported.output.write_to(out_dir, false)?;
```

`protoledger::Appender` appends to a ledger file with an exclusive lock and an
fsync per event, for programs that write ledgers live.
